## 2024-05-18 - [Fix information disclosure in production]
**Vulnerability:** The application was leaking potentially sensitive error information to the client in the `/api/chat` and `/api/send-otp` endpoints. Additionally, the OTP generation function was logging the code to the console client-side in the `signup` page.
**Learning:** Returning standard system error messages back directly to the client can lead to unintentional information exposure (e.g. details about environment or unexpected api behaviour). Client-side generated OTPs should never be logged. Note that client side generated OTPs are a structural anti-pattern.
**Prevention:** Implement secure error handling by returning generic error messages in API routes. Avoid `console.log` statements in client-side code, especially those that generate sensitive information.

## 2024-05-18 - [Fix weak random number generation for OTP]
**Vulnerability:** The application was using `Math.random()` to generate a 4-digit OTP on the client side, which is cryptographically insecure and predictable.
**Learning:** `Math.random()` is not suitable for generating security-sensitive values like OTPs, tokens, or passwords, as its PRNG algorithm is predictable.
**Prevention:** Always use cryptographically secure random number generators (CSPRNG) like `window.crypto.getRandomValues()` in the browser or `crypto.randomBytes()` in Node.js for security-related random generation.

## 2024-05-18 - [Add Input Validation in API Routes]
**Vulnerability:** Missing input validation in `/api/chat` could allow excessively large payloads or invalid schemas, leading to unhandled server errors.
**Learning:** API route payloads generated by frontend components (like `FloatingChat.tsx`) must be strictly validated on the backend. The custom `ChatMessage` structure uses `text` instead of `content`.
**Prevention:** Validate array length, data types, and string bounds strictly before processing.


## 2024-05-18 - [Fix SMS injection vulnerability in OTP route]
**Vulnerability:** Missing format validation on the `otp` parameter in `/api/send-otp/route.ts`. Since this parameter is directly interpolated into an outgoing SMS message (`Your AgriLanka OTP verification code is ${otp}.`), an attacker could potentially pass arbitrarily long or malformed strings, leading to SMS injection/spoofing, phishing attacks on users, or unexpected API behavior from the upstream SMS gateway provider.
**Learning:** All user-provided data that is interpolated into outbound communications (like SMS or Email templates) MUST be strictly validated on the server side to ensure it matches the expected format (e.g., exactly 4 digits) before being processed or dispatched.
**Prevention:** Implement strict type checking and regex validation for all expected parameters in API routes, especially before concatenating them into templates for external services.
