## 2024-05-24 - [Avoid continuous scroll state]
**Learning:** Storing the raw window scroll coordinate (e.g. `window.scrollY`) in a React state variable causes the component to re-render on *every single scroll tick*. When this state is used as a dependency in a `useEffect` that attaches a scroll listener, it forces the listener to be constantly removed and re-attached, destroying performance.
**Action:** When determining visibility or threshold states on scroll, compute the boolean condition (`window.scrollY > 10`) and only update state if that boolean value changes (which React `useState` does implicitly when setting the same primitive boolean). Do not store the raw scroll number in state unless absolutely necessary for an animation frame, and even then prefer `useMotionValue` or similar non-react-state primitives.
## 2024-10-11 - [Optimize O(N^2) lookups and excessive array filtering in Next.js components]
**Learning:** Performing `Array.find()` inside a `Array.map()` creates an O(N^2) operation. When dealing with arrays of thousands of elements (like raw API price data), this creates a significant blocking operation on the main thread during render. Similarly, repeatedly filtering the same large array inside multiple `useMemo` hooks is highly inefficient.
**Action:** When mapping over items and needing to look up related data from a large array, always pre-compute a `Map` (O(N) to build) and use `Map.get()` (O(1) lookup) inside the map. If a component filters a large global dataset down to a subset, memoize that subset first and use it as the source for subsequent derived calculations to reduce the dataset size for N-dependent operations.
